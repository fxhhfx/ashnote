# 灰烬笔记 AshNote

> 阅后即焚的一次性加密链接。内容在浏览器里加密，服务端只存密文，读一次就从边缘节点抹掉。

![edge](https://img.shields.io/badge/Edge-ESA%20Pages-ff6b35) ![crypto](https://img.shields.io/badge/Crypto-AES--256--GCM-6b3fff)

## 这是什么

我们每天都要在微信、钉钉、邮件里传密码、API Key、临时凭证。这些消息会一直留在对方的聊天记录和服务器里，删了也可能有备份。

灰烬笔记解决的问题很简单：**把"只能看一次"变成默认规则。**

- 内容在浏览器端用 AES-256-GCM 加密，密钥只存在于链接的 `#` 片段中（浏览器不会把 `#` 后面的内容发给服务器）
- 服务端（ESA 边缘函数）拿到的只有密文，即使数据库被拖走也无法解密
- 对方打开链接后，密文立即从边缘 KV 中删除，第二次访问只会看到"已经烧掉了"
- 发送方还能通过管理链接确认对方是否已读、剩余时间，或提前销毁

## 功能

| 功能 | 说明 |
| --- | --- |
| 端到端加密 | 明文与密钥不出浏览器，服务端零知识 |
| 双模式 | 链接模式（点开即看）/ 口令模式（额外口令，PBKDF2 派生密钥） |
| 一次性 | 链接模式交付即焚；口令模式解密成功后才焚毁，输错不消耗内容 |
| 有效期 | 1 小时 / 1 天 / 7 天，过期自动销毁 |
| 阅读回执 | 创建者可查询"未读 / 已读 / 已过期"，不泄露内容 |
| 提前销毁 | 管理链接可随时手动焚毁 |
| 防收录 | 全站 `noindex`，接口 `no-store`，不进入搜索引擎和 CDN 缓存 |

## 技术架构

全部构建在阿里云 ESA 的边缘能力上：

```
浏览器
  │  AES-256-GCM 加密（WebCrypto）
  ▼
ESA Pages 静态资源  ── 命中即返回（首页 / 查看页 / 状态页）
  │  未命中
  ▼
ESA 边缘函数（src/index.js，单入口）
  │  按 pathname 路由 /api/*
  ▼
ESA Edge KV（namespace: ashnote）
   写入密文、记录状态、删除密文
```

| ESA 能力 | 在项目中的用途 |
| --- | --- |
| **Pages 静态托管** | 三个页面纯静态，全球边缘节点直出，无回源 |
| **边缘函数** | 创建 / 读取 / 焚毁 / 状态 / 计数 五个接口，跑在离用户最近的节点 |
| **Edge KV** | 存密文与状态；读取成功后立即置空密文字段 |
| **缓存策略** | 静态资源长缓存；`/api/*` 全部 `no-store`；`/api/stats` 允许 30 秒公共缓存削峰 |

### 关键设计

**1. 密钥不上服务器**

分享链接形如 `https://xxx/v/#i=<id>&m=link&k=<key>`。`#` 后面的部分由浏览器自己解析，永远不会出现在 HTTP 请求里。服务端只有 `id`，没有 `key`，因此即使日志被看到也解不开内容。

**2. 为什么口令模式要"延迟焚毁"**

链接模式可以做到交付即焚。但口令模式下，如果先焚毁再让用户输口令，口令一输错内容就永久丢了。所以采取两阶段：

1. `/api/read` 返回密文，状态置为 `reading`
2. 浏览器解密成功 → `/api/burn` 确认焚毁

输错口令时密文仍在，可以重试；解密成功后才真正删除。

**3. 状态与内容的分离**

读取后不直接删除记录，而是写入一条不含密文的"墓碑"（`state: "read"`）。这样发送方仍能确认"对方确实读过了"，但内容已经不存在。记录本身非常小。

## 本地开发

项目是零依赖纯静态 + 单文件边缘函数，不需要构建。

```bash
# 完整本地联调：把 static + /api/* 都跑起来（内存版 KV，重启即清空）
python dev/mock_server.py
# 打开 http://127.0.0.1:8787
```

`dev/mock_server.py` 只是本地开发用的接口替身，部署时不会上传。

## 部署到 ESA Pages

1. 登录 [ESA 控制台](https://esa.console.aliyun.com/)，进入 **边缘计算和 AI → 函数和 Pages**
2. 新建 Pages，选择关联本 GitHub 仓库
3. 构建配置由仓库根目录的 `esa.jsonc` 自动接管（无安装、无构建命令，静态目录 `./public`，入口 `./src/index.js`）
4. 进入 **边缘存储**，创建一个名为 `ashnote` 的存储空间（必须同名，代码中硬编码）
5. 重新部署，拿到 `https://xxxx.er.aliyun-esa.net` 访问地址

> 如果存储空间想用别的名字，改 `src/index.js` 里的 `NS` 常量即可。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/create` | `{ct, iv, mode, ttl}` → `{id, mgmt, expiresAt}` |
| POST | `/api/read` | `{id}` → `{state, ct, iv, mode}`，链接模式立即焚毁 |
| POST | `/api/burn` | `{id}` → 确认焚毁（口令模式用） |
| POST | `/api/status` | `{id, mgmt}` → 状态与时间 |
| POST | `/api/destroy` | `{id, mgmt}` → 提前销毁 |
| GET | `/api/stats` | 当前未读数量，边缘缓存 30 秒 |

## 已知限制

- Edge KV 为最终一致，极端并发（毫秒级同时打开同一链接）下有极小概率被读到两次
- 单条内容上限 100KB（受 KV 1.8MB 与 base64 膨胀限制）
- 过期记录不会主动清理，仅在下次访问时惰性销毁
